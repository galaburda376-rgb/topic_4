# Классификация спама и кликбейта в Telegram-сообщениях

Отчёт по домашнему заданию, кейс4

Кейс 4: «Классификация спама и кликбейта: распознавание спам-сообщений и
кликбейт-заголовков». Цель- разработать систему, которая классифицирует
текстовые сообщения из Telegram на два класса: spam (нежелательные
сообщения — рекламные, мошеннические, автоматические) и clickbait

Репозиторий проекта: https://github.com/galaburda376-rgb/topic_4

## Описание датасета

Готового размеченного датасета спама/кликбейта из Telegram в открытом доступе
найти не удалось,  поэтому датасет я сгенерировал сам ( с помощью LLM моделей) — шаблонами со случайной подстановкой слов (`data/generate_dataset.py`). Получилось 6000 сообщений, поровну на класс (3000 spam, 3000 clickbait), разбил на train/val/test в пропорции 70/15/15 (4200/900/900).

Для каждого класса написал пиерно по ~10 шаблонов с словарями-слотами (суммы,
офферы, темы, субъекты и т.д., от 5 до 25 вариантов на слот) — так получаются
тысячи уникальных комбинаций, а не повторяющиеся фразы. Отдельно добавил
25% "пограничных" сообщений на класс, где специально смешана лексика двух
категорий (например, спам в форме кликбейт-заголовка: «Вы не поверите, как я
заработал 50.000₽!») — без этого классы разделялись по словарю идеально и
анализировать ошибки было бы просто не на чем.

Каетсвео данных:  всё на русском, UTF-8 , без пропусков,
средняя длина — 12 токенов. Специально внёс два вида шума с
задокументированной долей:

- опечатки в тексте (слипшиеся слова, повторы/пропуски букв) — 14.9% сообщений;
- шум разметки — 5.1% сообщений, которым намеренно перепутали метку класса,
  чтобы смоделировать реальную ситуацию, когда авторазметка или разметчики
  иногда ошибаются.

Получается, «чистых» сообщений без обоих видов шума — около 81%.

TTS-часть кейса в данной работе не реализовывалась.

## Предобработка

Один метод предобработки, реализован в `src/preprocessing.py`:

1. нижний регистр;
2. удаление URL и упоминаний (`@username`, `#hashtag`);
3. токенизация, удаление пунктуации и эмодзи;
4. удаление стоп-слов (свой список);
5. лемматизация через `pymorphy3`.
Лемматизация оказалась важна: без неё "скидка", "скидки", "скидкой" TF-IDF
считает тремя разными признаками. После предобработки среднее число токенов
на сообщение синзилось с 12 до 7.6.

## Метод классификации

### Baseline: TF-IDF + логистическая регрессия
`src/train_baseline.py`. Выбор пал на этот метод, потому что:

- TF-IDF хорошо выделяет "маркерные" слова каждого класса ("скидка", "доход",
"переходи" у спама; "шок", "не поверите", "фактов" у кликбейта) — именно на
таких словах и строится разница между классами в наших данных;
- логистическая регрессия поверх TF-IDF — надёжный, быстрый baseline для коротких текстов, не переобучается на датасете из нескольких тысяч примеров и выдаёт вероятности классов, которые потом нужны для ансамбля;
- это метод из вебинара 4, трансформеры не используются.
Параметры: TF-IDF с n-граммами (1,2), `min_df=2`, `max_df=0.95`;
`LogisticRegression(C=5.0)`.

### Доп: ансамбль RNN + CNN
`src/train_rnn_cnn_ensemble.py`. Идея — RNN (BiLSTM) читает текст
последовательно и ловит порядок слов, CNN (свёртки с окнами 3/4/5 + max-pooling)
ловит характерные словосочетания независимо от их позиции в сообщении. Обе
сети учат embedding с нуля на train-выборке, никаких предобученных моделей.

Предсказания двух сетей усредняем с весом `p = w·p_RNN + (1−w)·p_CNN`, вес `w`
подбираем перебором на валидации (шаг 0.05), а не на глаз — иначе оценка
была бы нечестной.

### Результаты на тесте (900 сообщений)
Модель\Accuracy
Baseline (TF-IDF + LogReg)\0.9422
RNN (BiLSTM)\0.9422
CNN\0.9422
Ансамбль (RNN+CNN)\0.9422

Лучший вес ансамбля это  `w_RNN = 0.95`, `w_CNN = 0.05` валидация отдала почти
весь вес RNN, то есть выигрыша от смешивания с CNN на этих данных почти нет

## Анализ ошибок
Самое интересное:все четыре модели ошиблись на одном и том же наборе из
52 сообщений -- проверили сравнением `results/baseline_misclassified.csv` и
`results/ensemble_misclassified.csv`, полное совпадение.

И Когда сопоставил эти 52 ошибки с колонкой `is_label_flipped` (помечает
сообщения с намеренно перепутанной меткой), оказалось — это ровно те еж самые
52 сообщения. То есть ни одной "содержательной" ошибки, где модель реально
перепутала бы класс по смыслу текста, на тесте нет.

Примеры (текст → метка в датасете → предсказание модели):
- «7 секретов заработка, которые скрывают банки. Переходи по ссылке в
описании» → датасет: `clickbait` → модель: `spam`
- «5 фактов про воспитание детей, от которых вы будете в шоке» → датасет:
`spam` → модель: `clickbait`
- «Уникальное предложение: заработок на дому уже сегодня. Регистрируйся по
ссылке!» → датасет: `clickbait` → модель: `spam`

В каждом случае предсказание модели логичнее, чем метка в датасете — то есть
модель не ошиблась, а правильно определила содержание текста, а "эталон" в
этих случаях специально испорчен.

Вывод, — все методы с задачей справляются одинаково хорошо, разделять там особо нечего, кроме испорченных меток, которые принципиально нельзя угадать правильно по тексту. На реальныхTelegram-данных, где граница между спамом и кликбейтом менее чёткая, разница между моделями и выигрыш от ансамблирования, думаю была бы заметнее.
